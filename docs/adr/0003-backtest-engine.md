# ADR 0003: 回测引擎 MVP 自己写（不用 vectorbt）

> 状态：Accepted
> 日期：2026-09-15
> 决策者：liubo

## 背景

回测引擎选型有两条路：

1. **自己写**（日循环 + pandas）—— 简单、透明、易调试
2. **用 vectorbt**（向量化）—— 快，但学习曲线陡

## 决策

**MVP 自己写日循环**，vectorbt 留到 v0.2。

## 理由

1. **MVP 数据量小**：单策略 5-10 个标的 × 5 年 = ~1250 天，日循环跑 1ms 级，无性能压力
2. **可调试**：每一步都能 print，vectorbt 一报错就是"在某个 broadcast 那里错了"
3. **可读**：spec 050 的伪代码能 1:1 翻译成 Python
4. **liubo 没用过 vectorbt**：学习成本 > 收益
5. **教学价值**：回测引擎是 quant 入门必学，自己写一遍更懂

## 后果

- **正面**：代码可读、可改、确定性强
- **负面**：10 标的 × 10 年的场景会到秒级，规模化时不够
- **缓解**：
  - 架构上把"日循环"和"指标计算"解耦，v0.2 只换循环部分
  - vectorbt 已经在 pyproject.toml 的 `[backtest]` extras 里备好

## 备选方案

| 方案 | 否决理由 |
| --- | --- |
| backtrader | 事件驱动，老派，文档差 |
| zipline | 不再活跃维护 |
| vectorbt | 学习曲线陡，MVP 不需要 |
| quantstats | 只做指标，不做回测 |
