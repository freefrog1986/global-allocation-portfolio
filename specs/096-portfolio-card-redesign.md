# Spec 096: 周报卡片重设计（实盘持仓部分）

> 状态：Draft
> 最后更新：2026-09-18（第二轮反馈）
> 作者：liubo
> 实现 PR（如果有）：TBD
> 依赖：spec 090（实盘账本）、spec 095（breakdown 大类资产分类）

## 目标

把 `gap portfolio publish` 发出的周报卡片**聚焦在「实盘持仓」一个模块**，删掉次要内容、重新组织信息层次，让用户在飞书里一眼看明白自己现在持有什么、各占多少。

## 不在范围内

- 不动 specs/090（数据模型 / 交易流水 / 快照）— spec 090 的所有数据接口保持不变
- 不动 breakdown.py（14 个 Swensen 子类划分已经定）— 只改展示形式
- 不发其他类型的卡（持仓预警、交易确认等都不在本 spec 范围）
- 不做 sleeve / strategy drift 对比（属于 spec 091 后续）
- 不加图表交互（drill-down / tooltip 增强）

## 设计原则（第六轮反馈修订）

只回答用户三个问题：
1. **现在整体怎么样**（summary div 顶部 — 总市值 / 盈亏 / 周涨跌 / 累计涨跌）
2. **大类资产怎么分布**（柱状图，按 Swensen 框架顺序，纵坐标 = 占比 %）
3. **每个大类持多少**（聚合表，1 行 = 1 个 Swensen 大类）

**第六轮反馈关键变化**（liubo 2026-09-18）：
- 柱状图 Y 轴数字加 **% 后缀**（之前是 "29.9"，现在 "29.9%"）
- 用 VChart 标准 axis formatter：`axes[*].label.formatMethod = 'val => val + "%"'`

**第五轮反馈关键变化**（liubo 2026-09-18）：
- 持仓表 **# 信息嵌进分类名前缀**（"1. A 股股票"），干掉单独的 # 列
- 原因：Feishu table column width 实测只接受 `"auto"`，其它值（`short`/`medium`/`long`/数字）都被 API 拒（HTTP 230099 "table column width is invalid"）—— 无法把 # 列做窄，干脆把 # 信息合到 class 里

**第四轮反馈关键变化**（liubo 2026-09-18）：
- 柱状图纵坐标数字保留 **1 位小数**（不要再 2 位，太长）
- 表 **# 列宽度改窄** —— 后来发现 Feishu table 不支持自定义宽度（第五轮折中）

**第三轮反馈关键变化**（liubo 2026-09-18）：
- 柱状图 **纵坐标改成占比**（不再是市值）—— weight 0~1 转成 0~100 百分比数字
- 柱状图标题改成"各大类资产占比（%，按 Swensen 框架顺序）"明示单位
- 持仓表 **加序号列**（第 1 列，1-indexed，1~14）—— 让用户一眼看到 Swensen 框架总数（后来合并到 class 前缀）

**第二轮反馈关键变化**（liubo 2026-09-18）：
- 柱状图 **不再按市值倒序**，改按 **Swensen 框架顺序**（A 股 → 港股 → 美股 → 欧 → 亚 → 新兴 → 全球 → REITs → 利率债 → 信用债 → 美债 → 商品 → 现金）
- 持仓表 **不再下钻到单只基金**，只到"大类聚合"，3 列：分类 / 市值 / 占比
- 柱状图 + 表都展示 **全部 14 个子类**（含 count=0 的——空子类 weight=0 / 0.00%，方便看到框架里哪些没覆盖到）

## API 概览

`build_portfolio_card(journal, title=None)` 返回 `dict[str, object]`，3 段元素 + footer：

```
elements:
  1. div（lark_md）  # summary：标题 / 时间 / 总市值 / 总成本 / 浮动盈亏 / 周涨跌 / 累计涨跌
  2. chart          # 各大类资产市值柱状图（vertical bar，按 Swensen 框架顺序，14 类全展示）
  3. table          # 大类资产聚合表（按 Swensen 框架顺序，3 列：分类 / 市值 / 占比）

footer:
  note: "Generated by gap @ <时间>"
```

内部 helper：
- `_build_summary(journal, title) -> str` — 保持现状
- `_build_breakdown_bar(journal) -> dict[str, object]` — vertical bar，Swensen 顺序，全 14 类
- `_build_holdings_table(journal) -> dict[str, object]` — 大类聚合，3 列

删除的 helper（spec 090 写的那些）：
- `_build_pie`（当前持仓饼图）— 删
- `_build_history_line`（历史 NAV 折线）— 删
- `_build_recent_transactions`（最近 10 笔交易）— 删
- `_build_breakdown_table`（大类资产表格 — 旧版 5 列带 count）— 由聚合版（3 列无 count）替换

## 数据契约

**柱状图 chart_spec**（Feishu VChart simple 格式 `type: "bar"`）：

> 重要：用 **simple 格式**（`data.values` + `xField` + `yField`），不是 rich 的 `x_axis`/`series` 格式。飞书 VChart 柱状图 type 字段名是 `"bar"`（不是 `"column"`，那是 VChart 内部名）。
> 之前误用 `type: "column"` + rich 格式发了两次都被飞书 API 拒掉（HTTP 230099：chart spec is invalid），第三次查官方文档才改成 simple 格式 + `type: "bar"`，飞书接受。

```python
{
  "type": "bar",                           # 飞书对外只认 "bar"（垂直柱状图默认就是 column）
  "title": {"text": "各大类资产占比（%，按 Swensen 框架顺序）"},
  "data": {
    "values": [
      {"class": "A 股股票",       "weight": 29.92},    # 枚举位置 0，占比 29.92%
      {"class": "港股",           "weight": 31.96},    # 枚举位置 1，占比 31.96%
      {"class": "美股股票",       "weight": 5.94},     # 枚举位置 2
      {"class": "欧洲发达市场股票", "weight": 0},       # 枚举位置 3（空子类）
      {"class": "亚洲发达市场股票", "weight": 1.43},    # 枚举位置 4
      ...
      {"class": "现金",           "weight": 5.22},     # 枚举位置 13
    ]
  },
  "xField": "class",                        # X 轴 = 类名（中文）
  "yField": "weight",                       # Y 轴 = 占比 %（0~100）
  "legends": {"visible": False},
}
```

规则：
- 按 `SwensenClass` 枚举顺序展示全部 14 个子类（**不是**市值倒序）
- 不再过滤 `count == 0` 的子类——空子类 weight=0 不画柱子但保留 X 轴标签
- weight 原始值是 Decimal(0~1)，实现层 ×100 转成百分比数字交给 VChart
- 第四轮反馈：Y 轴数字 round 到 1 位小数（不要再 2 位）
- 第六轮反馈：Y 轴 label 用 VChart `axes[*].label.formatMethod = 'val => val + "%"'` 加 % 后缀
- 不加 `direction: "horizontal"` —— 默认就是垂直柱状图

**持仓聚合表 table spec**（按 Swensen 大类聚合）：
```python
{
  "columns": [
    {"name": "class",  "display_name": "分类",   "data_type": "text", "width": "auto"},
    {"name": "value",  "display_name": "市值(¥)", "data_type": "text", "width": "auto"},
    {"name": "weight", "display_name": "占比",   "data_type": "text", "width": "auto"},
  ],
  "rows": [
    {"class": "1. A 股股票",       "value": "57,270.73", "weight": "29.92%"},
    {"class": "2. 港股",           "value": "61,188.26", "weight": "31.96%"},
    ...
    {"class": "4. 欧洲发达市场股票", "value": "0.00",     "weight": "0.00%"},
    ...
    {"class": "14. 现金",           "value": "10,000.53", "weight": "5.22%"},
  ]
}
```

规则：
- row 必须是 dict（Feishu API 强制，spec 095 已经踩过这个坑）
- 所有列 data_type=text（class / value / weight 全是预格式化字符串）
- 第五轮反馈：# 信息嵌进 class 前缀（"1. A 股股票"），干掉单独 # 列
- 所有列 width="auto"（Feishu table 实测只接受 "auto"，其它值 API 全拒）
- **不再按市值倒序排**，按 SwensenClass 枚举顺序排（跟柱状图一致）
- 展示全部 14 个子类（含 count=0 的——value="0.00" / weight="0.00%"）
- **不再下钻到单只基金**——不显示 code / name / count 列

**summary 文本**（保持现状）：
```
**{title}**
**生成时间**：2026-09-18 21:41
**总市值**：191,440.96 CNY
**总成本**：166,340.52 CNY
**浮动盈亏**：+25,100.44 (+15.09%)
**上周涨跌**：n/a
**累计涨跌**：n/a
```

## 边界情况

| 情况 | 处理 |
| --- | --- |
| 没有任何 holdings | 跟现状一致，raise `ValueError("没有持仓，无法生成卡片")` |
| 有 holdings 但所有子类都是未知的（SUBCLASS_BY_CODE 没收录） | bar chart 14 个值都是 0；holdings table 14 行全部 "0.00" / "0.00%"。**不阻塞** |
| 子类里有 `market_value is None` | compute_breakdown 已过滤（`h.market_value is None` → 跳过） |
| 单只基金市值 > 总市值的 99% | bar chart 跟 table 都会显示；不算 bug |
| 同一只基金多笔 buy | `compute_holdings` 已经按基金聚合，天然不会重复 |

## 备注

**为什么删 pie chart**：12 个子类 + 31 只基金挤在一张饼图里几乎看不清，bar chart 在数量比较多的时候更易读，且 bar 直接显示绝对金额（不是比例），对"我现在哪类资产最多"的诉求更直接。

**为什么删 NAV line chart**：跟"实盘持仓"主题无关（NAV 走势是 spec 091 / 093 之后 sleeve / drift 模块的内容）。如果以后想看历史曲线，spec 093 单独发一张策略监控卡。

**为什么删最近交易**：交易流水是 journal 数据，不是"当前持仓"的一部分。spec 090 已经把交易存在 SQLite 里，要看的时候直接 `gap portfolio tx list` 查，不需要塞进卡片占位置。

**为什么删持仓明细（单只基金）**：第二轮反馈明确指出"不细致到具体基金"。用户的诉求是"我每个大类持了多少"，单只基金的明细在交易流水 / journal 里查，不需要塞进卡片占位置。如果以后想要，spec 单独发一张"持仓明细卡"（drill-down 卡片，hover chart bar 触发）。

**为什么按 Swensen 框架顺序排**：市值倒序适合"现在哪类最多"，但用户更关心"我的资产配置是否符合 Swensen 框架"。框架顺序排能让用户一眼看出"框架里哪些子类占比过高 / 过低 / 没覆盖到"。

**为什么展示 count=0 的子类**：持仓现状应反映"我配置了什么 + 没配置什么"。空子类用 0 值显示 = 一个明显的提醒信号（"我没有欧洲发达市场股票 / 没有国内利率债"）。

**为什么保留 summary div**：标题 + 总市值 + 盈亏是最快的"我整体怎么样"信号，3 行字承载信息密度最高。
