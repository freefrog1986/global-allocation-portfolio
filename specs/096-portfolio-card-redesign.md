# Spec 096: 周报卡片重设计（实盘持仓部分）

> 状态：Draft
> 最后更新：2026-09-18
> 作者：liubo
> 实现 PR（如果有）：TBD
> 依赖：spec 090（实盘账本）、spec 095（breakdown 大类资产分类）

## 目标

把 `gap portfolio publish` 发出的周报卡片**聚焦在「实盘持仓」一个模块**，删掉次要内容、重新组织信息层次，让用户在飞书里一眼看明白自己现在持有什么、各占多少。

## 不在范围内

- 不动 specs/090（数据模型 / 交易流水 / 快照）— spec 090 的所有数据接口保持不变
- 不动 breakdown.py（14 个 Swensen 子类划分已经定）— 只改展示形式（bar 替 table）
- 不发其他类型的卡（持仓预警、交易确认等都不在本 spec 范围）
- 不做 sleeve / strategy drift 对比（属于 spec 091 后续）
- 不加图表交互（drill-down / tooltip 增强）

## 设计原则

只回答用户三个问题：
1. **现在持有什么**（summary div 顶部）
2. **大类资产怎么分布**（柱状图，一张图看完 12 个子类）
3. **具体买了哪几只**（holdings 明细表，按市值倒序）

## API 概览

`build_portfolio_card(journal, title=None)` 返回 `dict[str, object]`，3 段元素 + footer：

```
elements:
  1. div（lark_md）  # summary：标题 / 时间 / 总市值 / 总成本 / 浮动盈亏 / 周涨跌 / 累计涨跌
  2. chart          # 各大类资产市值柱状图（horizontal bar）
  3. table          # 持仓明细（按市值倒序，5 列：code / name / 分类 / 市值 / 占比）

footer:
  note: "Generated by gap @ <时间>"
```

内部 helper：
- `_build_summary(journal, title) -> str` — 保持现有
- `_build_breakdown_bar(journal) -> dict[str, object]` — 新增，horizontal bar chart
- `_build_holdings_table(journal) -> dict[str, object]` — 新增，holdings 明细

删除的 helper（spec 090 写的那些）：
- `_build_pie`（当前持仓饼图）— 删
- `_build_history_line`（历史 NAV 折线）— 删
- `_build_recent_transactions`（最近 10 笔交易）— 删
- `_build_breakdown_table`（大类资产表格）— 由 `_build_breakdown_bar` 替换

## 数据契约

**柱状图 chart_spec**（Feishu VChart simple 格式 `type: "bar"`）：

> 重要：用 **simple 格式**（`data.values` + `xField` + `yField`），不是 rich 的 `x_axis`/`series` 格式。飞书 VChart 柱状图 type 字段名是 `"bar"`（不是 `"column"`，那是 VChart 内部名）。
> 之前误用 `type: "column"` + rich 格式发了两次都被飞书 API 拒掉（HTTP 230099：chart spec is invalid），第三次查官方文档才改成 simple 格式 + `type: "bar"`，飞书接受。

```python
{
  "type": "bar",                           # 飞书对外只认 "bar"（垂直柱状图默认就是 column）
  "title": {"text": "各大类资产市值"},
  "data": {
    "values": [
      {"class": "港股",      "value": 61188.26},
      {"class": "A 股股票",  "value": 57270.73},
      ...
    ]
  },
  "xField": "class",                        # X 轴 = 类名（中文）
  "yField": "value",                        # Y 轴 = 金额
  "legends": {"visible": False},
}
```

规则：
- 只放 `count > 0` 的子类（空类不显示，跟原 table 一致）
- 数据按 `value` 降序排（spec 实现层排序，VChart 不需要 `sort: true`）
- value 单位是 CNY（chart 用 float，预格式化在 table 里才用 string）
- 不加 `direction: "horizontal"` —— 默认就是垂直柱状图（柱子向上长的那种）
- 如果想横向条形图，加 `"direction": "horizontal"` + 互换 xField/yField

**持仓明细 table spec**：
```python
{
  "columns": [
    {"name": "code", "display_name": "代码", "data_type": "text", "width": "auto"},
    {"name": "name", "display_name": "基金", "data_type": "text", "width": "auto"},
    {"name": "class", "display_name": "分类", "data_type": "text", "width": "auto"},
    {"name": "value", "display_name": "市值(¥)", "data_type": "text", "width": "auto"},
    {"name": "weight", "display_name": "占比", "data_type": "text", "width": "auto"},
  ],
  "rows": [
    {
      "code": "004098",
      "name": "前海开源港股通股息率50强",
      "class": "港股",
      "value": "54,399.47",
      "weight": "28.42%",
    },
    ...
  ]
}
```

规则：
- row 必须是 dict（Feishu API 强制，spec 095 已经踩过这个坑）
- 所有列 data_type=text（value / weight 是预格式化字符串带千分位 / %）
- 按 `market_value` 倒序排序
- 跳过 `market_value is None` 的持仓
- 分类列查 breakdown 的 `SUBCLASS_BY_CODE`，未知基金留空字符串

**summary 文本**（保持现状）：
```
**{title}**
**生成时间**：2026-09-18 21:41
**总市值**：191,440.96 CNY
**总成本**：166,340.52 CNY
**浮动盈亏**：+25,100.44 (+15.09%)
**上周涨跌**：n/a
**累计涨跌**：n/a
```

## 边界情况

| 情况 | 处理 |
| --- | --- |
| 没有任何 holdings | 跟现状一致，raise `ValueError("没有持仓，无法生成卡片")` |
| 有 holdings 但所有子类都是未知的（SUBCLASS_BY_CODE 没收录） | bar chart 只有 1 个空 data.values；holdings table 分类列全是空字符串。**不阻塞** — 不该让缺失 mapping 阻止卡片生成 |
| 子类里有 `market_value is None` | holdings table 跳过这条（不算进 total）；bar chart 跳过这条（`value` 不能是 None） |
| 单只基金市值 > 总市值的 99% | bar chart 跟 table 都会显示；不算 bug |
| 同一只基金多笔 buy（应只在 holdings 表里出现一次） | `compute_holdings` 已经按基金聚合，天然不会重复 |
| holdings 数量 > 50 | table 全部显示（不截断，因为是最关键的"我买了啥"）；如果未来真有性能问题再考虑截断 |

## 验收标准

- [ ] 卡片 `elements` 数量 = 3（summary div + bar chart + holdings table）+ 若干 hr 分隔符（= 5）
- [ ] 不再包含 type=pie 的 chart_spec
- [ ] 不再包含 type=line 的 chart_spec
- [ ] 不再包含交易流水 table（columns 不含 date / side / shares / strategy）
- [ ] bar chart `type == "bar"`，`xField == "class"`，`yField == "value"`
- [ ] bar chart data.values 长度 == 非空子类数（count > 0 的 SwensenClass）
- [ ] bar chart 按 value 降序
- [ ] holdings table 5 列：code / name / class / value / weight
- [ ] holdings table 所有 row 都是 dict
- [ ] holdings table 按 market_value 降序
- [ ] holdings table 跳过 market_value is None 的项
- [ ] holdings table 跳过 shares <= 0 的项（依赖 compute_holdings 的现有逻辑）
- [ ] ruff check + mypy strict 全绿
- [ ] 现有 31 只基金测试 + 新断言，全过

## 备注

**为什么删 pie chart**：12 个子类 + 31 只基金挤在一张饼图里几乎看不清，bar chart 在数量比较多的时候更易读，且 bar 直接显示绝对金额（不是比例），对"我现在哪类资产最多"的诉求更直接。

**为什么删 NAV line chart**：跟"实盘持仓"主题无关（NAV 走势是 spec 091 / 093 之后 sleeve / drift 模块的内容）。如果以后想看历史曲线，spec 093 单独发一张策略监控卡。

**为什么删最近交易**：交易流水是 journal 数据，不是"当前持仓"的一部分。spec 090 已经把交易存在 SQLite 里，要看的时候直接 `gap portfolio tx list` 查，不需要塞进卡片占位置。

**为什么保留 summary div**：标题 + 总市值 + 盈亏是最快的"我整体怎么样"信号，3 行字承载信息密度最高。
